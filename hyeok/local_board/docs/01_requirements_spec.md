# 요구사항 정의서 / 기능명세서

## 1. 문서 목적

이 문서는 Local Board 프로젝트에서 구현해야 하는 기능을 사용자 관점과 개발 관점으로 정리합니다.

프로젝트 기획서가 "무엇을 왜 만드는가"를 설명한다면, 기능명세서는 "무엇을 어떻게 동작하게 만들 것인가"를 정의합니다.

## 2. 서비스 개요

Local Board는 동네 주민들이 특정 가게나 지역 장소에 대해 질문하고, 댓글로 경험을 공유하며, AI가 DB에 쌓인 게시글과 댓글을 바탕으로 평가와 장소 추천을 제공하는 게시판 서비스입니다.

## 3. 사용자 유형

| 사용자 | 설명 |
| --- | --- |
| 비회원 | 게시글 목록과 상세 내용을 조회할 수 있습니다. |
| 회원 | 게시글 작성, 댓글 작성, 마이페이지 수정, AI 추천 기능을 사용할 수 있습니다. |
| 게시글 작성자 | 본인이 작성한 게시글을 수정/삭제할 수 있습니다. |
| 댓글 작성자 | 본인이 작성한 댓글을 삭제할 수 있습니다. |

## 4. 기능 우선순위

| 우선순위 | 기능 |
| --- | --- |
| P0 | 회원가입, 로그인, 게시글 CRUD, 댓글, 검색, 페이징 |
| P1 | 태그, 대댓글, 익명 댓글, 정렬, 마이페이지 |
| P2 | RAG 비슷한 게시글 추천, AI 태그 추천 |
| P3 | Agent 기반 DB 평가, MCP 기반 장소 추천 |

## 5. 상세 기능명세

### 5.1 회원가입

| 항목 | 내용 |
| --- | --- |
| 기능명 | 회원가입 |
| 사용자 | 비회원 |
| 입력값 | 이메일, 닉네임, 비밀번호 |
| 처리 | 이메일/닉네임 중복 검사 후 비밀번호를 해싱하여 사용자 저장 |
| 성공 결과 | 사용자 정보 반환 |
| 실패 조건 | 이메일 중복, 닉네임 중복, 입력값 누락 |
| 비고 | 비밀번호 원문은 DB에 저장하지 않습니다. |

### 5.2 로그인

| 항목 | 내용 |
| --- | --- |
| 기능명 | 로그인 |
| 사용자 | 회원 |
| 입력값 | 이메일, 비밀번호 |
| 처리 | 비밀번호 검증 후 JWT Access Token 발급 |
| 성공 결과 | access_token 반환 |
| 실패 조건 | 존재하지 않는 이메일, 비밀번호 불일치 |
| 비고 | 프론트엔드는 토큰을 저장한 뒤 인증 필요 API 호출 시 사용합니다. |

### 5.3 내 정보 조회

| 항목 | 내용 |
| --- | --- |
| 기능명 | 내 정보 조회 |
| 사용자 | 로그인 사용자 |
| 입력값 | Authorization Bearer Token |
| 처리 | 토큰 검증 후 현재 사용자 조회 |
| 성공 결과 | 사용자 id, email, nickname, bio 반환 |
| 실패 조건 | 토큰 없음, 토큰 만료, 잘못된 토큰 |

| 항목 | 내용 |
| --- | --- |

| 사용자 | 로그인 사용자 |

| 항목 | 내용 |
| --- | --- |

| 사용자 | 전체 사용자 |

| --- | --- |

| 사용자 | 전체 사용자 |

| 실패 처리 | Agent 실패 시 MCP 직접 검색으로 fallback |

## 6. 비기능 요구사항

| 항목 | 요구사항 |
| --- | --- |
| 보안 | 비밀번호 해싱, JWT 인증, `.env` 기반 시크릿 관리 |
| 성능 | 게시글 목록은 페이징 처리, RAG 후보 개수 제한 |
| 안정성 | AI/MCP 실패 시 fallback 처리 |
| 유지보수 | Router, Schema, Service, Model 역할 분리 |
| 사용성 | 로그인 필요 기능과 권한 오류를 명확히 표시 |

## 7. 제외 범위

- 네이버 지도 방문자 리뷰 본문 수집
- 결제 기능
- 실시간 채팅
- 관리자 페이지
- 이미지 업로드
- 정식 배포 환경의 HTTPS 구성
