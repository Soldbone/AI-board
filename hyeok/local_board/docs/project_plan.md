# Local Board 프로젝트 기획안

## 1. 프로젝트 개요

### 프로젝트명

Local Board: 우리동네 후기 기반 AI 장소 추천 게시판

### 한 줄 소개

동네 주민들이 직접 남긴 게시글과 댓글을 바탕으로, 특정 가게나 조건에 맞는 장소를 AI가 평가하고 추천해주는 지역 정보 공유 게시판입니다.

### 프로젝트 배경

네이버 지도, 카카오맵 같은 지도 서비스에서는 가게의 위치, 영업 정보, 별점, 리뷰를 확인할 수 있습니다. 하지만 실제 이용자에게 추가 질문을 하거나, 특정 상황에 맞는 후기를 모아서 판단하기는 어렵습니다.

예를 들어 사용자는 다음과 같은 질문을 하고 싶어합니다.

- "진샤이 가본 사람 있나요?"
- "둔전역 근처 조용한 카페 추천해주세요."
- "마평동에서 혼밥하기 괜찮은 중국집 있을까요?"
- "이 미용실 염색 잘하나요?"

기존 지도 리뷰는 정보가 많지만, 특정 질문에 맞춰 대화형으로 정리해주지는 않습니다. Local Board는 이 문제를 게시판과 AI 추천 기능으로 해결하고자 합니다.

## 2. 문제 정의

### 사용자가 겪는 문제

1. 지도 리뷰는 많지만 내 상황에 맞는 정보를 찾기 어렵습니다.
2. 특정 가게에 대해 추가 질문을 하고 싶어도 실제 이용자와 대화하기 어렵습니다.
3. 별점만으로는 메뉴, 분위기, 대기 시간, 가격, 혼밥 가능 여부 같은 세부 정보를 알기 어렵습니다.
4. 동네 주민들이 남긴 로컬 후기가 흩어져 있어 한 번에 판단하기 어렵습니다.

### 해결하고자 하는 방향

사용자가 동네 가게에 대해 질문하거나 후기를 남기면, 다른 사용자가 댓글로 경험을 공유합니다. 이후 AI는 DB에 쌓인 게시글과 댓글을 기반으로 해당 장소나 조건에 대한 평가를 요약하고, 필요하면 외부 장소 검색 결과를 함께 제공합니다.

## 3. 목표 사용자

### 주요 사용자

- 동네 맛집, 카페, 미용실, 옷가게 정보를 찾는 지역 주민
- 지도 리뷰만으로는 판단이 어려운 사용자
- 실제 이용자에게 질문하고 싶은 사용자
- 특정 조건에 맞는 장소를 빠르게 추천받고 싶은 사용자

### 사용 상황

- 처음 가보는 식당의 실제 후기가 궁금할 때
- 특정 메뉴나 서비스에 대한 경험담이 필요할 때
- 조용한 카페, 혼밥 식당, 가성비 좋은 가게처럼 조건 기반 추천이 필요할 때
- 동네 주민들의 평가를 모아서 보고 싶을 때

## 4. 핵심 가치

### 1. 질문 가능한 지역 후기 게시판

단순 리뷰 열람이 아니라, 사용자가 직접 궁금한 내용을 게시글로 남기고 댓글로 답변을 받을 수 있습니다.

### 2. DB 기반 AI 평가

AI가 외부 리뷰를 무작정 가져오는 것이 아니라, 우리 서비스 DB에 쌓인 게시글과 댓글을 먼저 탐색해 요약합니다. 이를 통해 서비스 내부 데이터가 쌓일수록 추천 품질이 좋아지는 구조를 만듭니다.

### 3. RAG 기반 유사 게시글 추천

게시글 작성 또는 상세 조회 시, 제목/본문/태그/댓글을 기반으로 비슷한 게시글을 추천합니다. 사용자는 같은 가게나 비슷한 조건의 기존 질문을 빠르게 확인할 수 있습니다.

### 4. MCP 기반 외부 장소 검색 보강

DB에 충분한 정보가 없거나 실제 장소 후보가 필요한 경우, Agent가 MCP 도구를 통해 네이버 지역검색 API를 호출하여 장소 후보와 지도 링크를 제공합니다.

## 6. AI 기능 설계

### RAG 역할

RAG는 우리 DB에 쌓인 게시글, 태그, 댓글을 탐색해 현재 사용자의 질문과 비슷한 데이터를 찾는 역할을 합니다.

현재 구현된 RAG 흐름은 다음과 같습니다.

```text
게시글 제목/본문/태그 입력
→ 핵심 키워드 추출
→ 기존 게시글의 제목/본문/지역/가게명/분류/태그/댓글과 비교
→ 유사도 점수 계산
→ 비슷한 게시글 목록 반환
```

### Agent 역할

Agent는 사용자의 요청을 보고 어떤 정보를 활용할지 판단합니다. 현재 프로젝트에서는 역할 범위를 좁혀, 다음 두 가지를 중심으로 동작합니다.

1. DB에 쌓인 관련 게시글과 댓글을 참고해 평가 요약
2. 필요한 경우 MCP 도구를 사용해 외부 장소 후보 검색

### MCP 역할

MCP는 Agent가 외부 시스템을 호출할 수 있도록 연결하는 도구 서버입니다. 우리 프로젝트에서는 별도의 MCP 서버를 두고, 네이버 지역검색 API와 이미지 검색 API를 호출하는 역할을 맡습니다.

현재 MCP 도구는 다음과 같습니다.

| 도구 | 역할 |
| --- | --- |
| health_check | MCP 서버 동작 여부 확인 |
| make_map_search_url | 지역과 키워드로 네이버 지도 검색 URL 생성 |
| search_local_places | 네이버 지역검색 API를 호출해 장소 후보 반환 |

### AI 추천 동작 흐름

```text
사용자가 게시글 상세 페이지에서 AI 장소 추천 클릭
→ 백엔드 Agent API 호출
→ DB에서 비슷한 게시글과 댓글 탐색
→ DB 기반 평가 요약 생성
→ Agent가 RAG 문맥을 참고
→ 필요한 경우 MCP 장소 검색 도구 호출
→ 프론트엔드에 DB 평가와 장소 추천 리스트 표시
```

## 9. 주요 사용자 시나리오

### 시나리오 1: 특정 식당 평가 확인

1. 사용자가 "진샤이 어때요?"라는 게시글을 확인합니다.
2. 상세 페이지에서 AI 장소 추천 버튼을 누릅니다.
3. AI가 DB에서 진샤이 관련 게시글과 댓글을 찾습니다.
4. 관련 후기가 있으면 DB 기반 평가를 먼저 보여줍니다.
5. 아래에는 네이버 지역검색 기반 장소 후보를 함께 보여줍니다.

### 시나리오 2: 조건 기반 장소 추천

1. 사용자가 "둔전역 근처 조용한 카페 추천해주세요"라는 글을 작성합니다.
2. RAG가 비슷한 게시글을 추천합니다.
3. 댓글로 실제 이용자 후기가 쌓입니다.
4. AI가 "조용한", "카페" 같은 조건을 검색 키워드로 잡습니다.
5. DB 평가와 외부 장소 검색 결과를 함께 제공합니다.

### 시나리오 3: 태그 기반 탐색

1. 사용자가 게시글 상세 페이지에서 태그를 클릭합니다.
2. 해당 태그가 포함된 게시글 목록으로 이동합니다.
3. 사용자는 같은 주제의 동네 정보를 빠르게 탐색할 수 있습니다.

## 12. 기대 효과

### 사용자 관점

- 동네 가게 정보를 더 구체적으로 물어볼 수 있습니다.
- 실제 이용자 댓글과 AI 요약을 함께 볼 수 있습니다.
- 비슷한 질문을 빠르게 찾을 수 있습니다.
- DB 후기가 부족할 때도 외부 장소 검색으로 최소한의 정보를 얻을 수 있습니다.

### 개발자 포트폴리오 관점

- React, FastAPI, PostgreSQL 기반 풀스택 구현 경험을 보여줄 수 있습니다.
- 인증, CRUD, 댓글, 태그, 검색, 페이징 등 기본 웹 서비스 기능을 포함합니다.
- RAG, MCP, Agent를 단순 개념이 아니라 실제 서비스 흐름에 연결했습니다.
- 외부 API 연동, 에러 처리, fallback 설계까지 설명할 수 있습니다.

## 13. 발표 시 핵심 메시지

이 프로젝트는 단순한 지역 게시판이 아니라, 사용자의 질문과 댓글이 쌓일수록 AI 추천의 근거가 강화되는 로컬 정보 플랫폼입니다.

발표에서는 다음 흐름을 강조할 수 있습니다.

```text
사용자 질문
→ 게시글/댓글 데이터 축적
→ RAG로 내부 후기 검색
→ Agent가 DB 평가 요약
→ MCP로 외부 장소 검색 보강
→ 사용자에게 평가와 장소 후보 제공
```

## 15. 결론

Local Board는 동네 주민들의 질문과 후기를 기반으로 성장하는 AI 지역 정보 게시판입니다. 단순히 외부 지도 데이터를 보여주는 것이 아니라, 서비스 내부에 쌓인 게시글과 댓글을 AI가 다시 활용한다는 점이 핵심입니다.

현재 구현된 기능은 기본 게시판 기능, 사용자 인증, 댓글/태그/검색, RAG 유사 게시글 추천, Agent 기반 DB 평가, MCP 기반 외부 장소 검색까지 포함합니다. 따라서 발표용 MVP로 충분한 완성도를 갖추고 있으며, 이후 데이터 품질과 검색 고도화를 통해 더 실용적인 서비스로 확장할 수 있습니다.
