# AI 기능 설계서

## 1. 문서 목적

이 문서는 Local Board의 AI 기능인 RAG, MCP, Agent가 각각 어떤 역할을 하고 어떻게 연결되는지 정리합니다.

## 2. AI 기능 전체 목표

Local Board의 AI 기능은 단순히 외부 장소를 검색하는 것이 아니라, 서비스 내부에 쌓인 게시글과 댓글을 먼저 활용해 사용자 질문에 맞는 평가와 추천을 제공하는 것을 목표로 합니다.

## 3. AI 기능 전체 흐름

```text
사용자 질문 게시글
→ RAG가 DB에서 관련 게시글/댓글 탐색
→ Agent가 DB 기반 평가 요약
→ 필요하면 MCP 장소 검색 도구 호출
→ 프론트엔드에 평가와 장소 추천 표시
```

## 4. RAG 설계

### RAG 역할

RAG는 내부 DB에서 사용자의 질문과 비슷한 게시글을 찾는 역할을 합니다.

### 검색 대상

| 대상 | 설명 |
| --- | --- |
| 제목 | 질문 핵심이 많이 포함됨 |
| 본문 | 구체적인 요청 내용 |
| 지역 | 용인 처인구, 창원 성산구, 사당역 등 |
| 가게명 | 특정 장소 질문의 핵심 |
| 분류 | 카페, 병원, 약국, 중식 등 |
| 태그 | 사용자가 붙인 키워드 |
| 댓글 | 실제 이용자 반응 |

### 키워드 추출 방식

```text
제목/본문/가게명 입력
→ kiwipiepy 형태소 분석
→ 명사/고유명사/영문/숫자 중심 추출
→ 불용어 제거
→ 태그 키워드 보강
```

### 불용어 예시

```text
궁금해요, 어때요, 후기, 추천, 실제, 이용, 방문, 가격, 대기, 시간, 사람, 분들
```

### 가게명 우선 규칙

문제:

```text
창원, 창원 성산구, 성산구 같은 지역 단어만으로 유사도가 높게 잡히면
서로 다른 가게 글이 섞일 수 있음
```

해결:

```text
store_name이 있으면
→ 후보 게시글의 가게명/제목/본문/태그/댓글에 해당 가게명이 포함된 경우만 사용
→ 그 후보 안에서 유사도 계산
```

### 필드 가중치

| 필드 | 가중치 |
| --- | ---: |
| 제목 | 4 |
| 가게명 | 4 |
| 태그 | 3 |
| 분류 | 2 |
| 지역 | 2 |
| 본문 | 1 |
| 댓글 | 1 |

## 5. Agent 설계

### Agent 역할

Agent는 사용자의 질문을 보고 다음을 판단합니다.

1. DB에 쌓인 정보로 어떤 평가를 할 수 있는가
2. 외부 장소 검색이 필요한가
3. 사용자에게 어떤 형태로 답변할 것인가

### Agent 입력값

| 입력 | 설명 |
| --- | --- |
| region | 지역 |
| title | 게시글 제목 |
| content | 게시글 본문 |
| keyword | 가게명 또는 분류 |
| display | 장소 검색 결과 개수 |
| RAG context | 관련 게시글/댓글 요약 |
| local_review_summary | DB 기반 사전 평가 |

### Agent 출력값

| 출력 | 설명 |
| --- | --- |
| answer | 사용자에게 보여줄 DB 기반 평가 문장 |
| local_review_summary | 관련 게시글/댓글 기반 평가 요약 |
| places | 추천 장소 리스트 |
| query | 실제 장소 검색 쿼리 |
| fallback_map_url | 직접 검색용 지도 링크 |
| reasoning_summary | Agent/MCP 사용 여부 설명 |
| tool_status | 도구 호출 상태 |

## 6. MCP 설계

### MCP 역할

MCP는 Agent가 외부 시스템을 호출할 수 있게 해주는 도구 서버입니다.

우리 프로젝트에서는 네이버 지역검색 API를 직접 Agent에 붙이지 않고, MCP 도구로 분리했습니다.

### MCP 도구

| 도구 | 설명 |
| --- | --- |
| health_check | MCP 서버 실행 확인 |
| make_map_search_url | 네이버 지도 검색 링크 생성 |
| search_local_places | 네이버 지역검색 API 호출 |

### MCP 장소 검색 응답

```json
{
  "query": "용인 처인구 갑짬뽕 처인구점",
  "places": [
    {
      "title": "갑짬뽕 처인구점",
      "category": "중식>중식당",
      "road_address": "주소",
      "naver_map_url": "https://map.naver.com/p/search/..."
    }
  ],
  "fallback_map_url": "https://map.naver.com/p/search/..."
}
```

## 7. fallback 설계

AI 기능은 외부 API와 LLM에 의존하므로 실패할 수 있습니다.

### fallback 조건

| 상황 | 처리 |
| --- | --- |
| Agent 타임아웃 | MCP 직접 검색으로 대체 |
| Agent 응답 비어 있음 | MCP 직접 검색으로 대체 |
| MCP 결과 없음 | 네이버 지도 fallback URL 제공 |
| RAG 결과 없음 | DB 후기 부족 메시지 제공 |

### fallback 흐름

```text
Agent 실행 실패
→ build_fallback_keyword로 검색어 생성
→ MCP search_local_places 직접 호출
→ 최소 장소 검색 결과 또는 지도 검색 링크 반환
```

## 8. 현재 한계

| 한계 | 설명 |
| --- | --- |
| 네이버 방문자 리뷰 미수집 | 공식 지역검색 API는 리뷰 본문을 제공하지 않음 |
| RAG 점수 단순함 | 현재는 키워드 매칭과 필드 가중치 중심 |
| 댓글 품질 의존 | DB에 쌓인 댓글이 부정확하면 평가도 약해짐 |
| LLM 비용 | Agent 호출 시 OpenAI API 사용 |
