프로젝트 속 RAG

이 프로젝트의 RAG는 “게시판에 쌓인 냉장고 재료 고민과 댓글 조언을 AI 추천의 근거로 쓰는 구조”입니다. 사용자가 새 추천을 요청하면, 서비스는 먼저 비슷한 게시글과 댓글을 찾고 그 근거를 LLM에게 전달합니다.

한 문장으로 설명하면
RAG는 AI가 바로 대답하게 하지 않고, 먼저 우리 서비스 안의 게시글과 댓글을 검색해서 “이 추천이 왜 나왔는지” 설명할 근거를 붙이는 방식입니다.
검색 대상 게시글 제목, 본문, 태그, 댓글 일부를 묶은 추천용 문서입니다.
검색 방법 문서를 임베딩 벡터로 바꾸고 pgvector로 유사한 게시글을 찾습니다.
추천 근거 질문글 본문이 아니라 댓글의 조리 팁과 답변을 핵심 근거로 사용합니다.

먼저 잡을 개념

개념 이 프로젝트에서의 의미 헷갈리기 쉬운 점
Embedding 문장이나 게시글을 숫자 배열로 바꾼 표현입니다. AI 답변이 아니라, 검색을 위한 좌표에 가깝습니다.
pgvector PostgreSQL 안에서 벡터 유사도 검색을 하게 해주는 확장입니다. 새 DB가 아니라, 기존 PostgreSQL에 벡터 검색 능력을 붙이는 선택입니다.
Similarity 요청 문서와 기존 게시글 문서가 의미적으로 얼마나 가까운지 보는 점수입니다. 점수가 높아도 댓글 근거가 없거나 재료가 안 겹치면 제외됩니다.
COMMUNITY_RAG 비슷한 커뮤니티 게시글을 1개 이상 근거로 사용한 추천입니다. 검색 결과가 있다는 것만으로 충분하지 않고, 품질 필터를 통과해야 합니다.
GENERAL_AI 커뮤니티 근거 없이 현재 요청과 일반 요리 지식으로 만든 추천입니다. 실패가 아니라, 근거가 부족할 때 정직하게 분기하는 정상 경로입니다.

모듈 지도

RAG 추천은 한 파일에 전부 들어 있지 않습니다. 컨트롤러는 입구, 서비스는 흐름 조립, 임베딩 서비스는 검색용 벡터 생성, LLM 서비스는 최종 추천 문장 생성, Prisma 모델은 근거 저장을 담당합니다.

입구
AiRecommendationsController 사용자의 추천 생성, 추천 조회, 상태 조회 요청을 받아 서비스로 넘깁니다.
오케스트레이션
AiRecommendationsService 게시글 조회, RAG 문서 생성, 유사 게시글 검색, 추천 저장까지 전체 흐름을 묶습니다.
검색 좌표
EmbeddingService 텍스트를 벡터로 만들고, 필요하면 로컬 해시 기반 임베딩으로 대체합니다.
추천 생성
RecipeLlmService RAG 근거와 현재 요청을 바탕으로 메뉴명, 이유, 조리 내용을 생성합니다.

게시글 기준 추천 흐름

사용자가 특정 게시글에서 AI 추천을 누를 때의 흐름입니다. 공부할 때는 “현재 게시글을 검색 질문으로 만들고, 과거 게시글을 후보 문서로 만든다”고 생각하면 쉽습니다.

1

요청 진입

create(postId, requesterId, dto)가 실행되고, 추천 목표와 추가 요청을 정리합니다.

2

현재 게시글 확보

findRagPost()가 제목, 본문, 태그, 댓글, 조회 수를 가져옵니다.

3

검색용 문서 만들기

buildRagDocument()가 게시글 정보를 하나의 긴 텍스트로 묶습니다.

4

임베딩 생성과 저장

EmbeddingService.embed()가 벡터를 만들고 upsertRagDocument()가 DB에 저장합니다.

5

후보 게시글 준비

현재 게시글을 제외한 최근 게시글을 후보로 가져와 각각 RAG 문서를 최신화합니다.

6

유사 게시글 검색

findSimilarPostsWithPgvector()가 벡터 거리 기준으로 가까운 게시글을 찾습니다.

7

근거 품질 필터링

isStrongSimilarPost()가 유사도, 댓글 근거, 재료 겹침 기준을 확인합니다.

8

추천 생성

RecipeLlmService.createRecommendation()이 커뮤니티 근거 또는 일반 지식 기반으로 추천 초안을 만듭니다.

9

추천과 참고글 저장

추천 결과와 참고 게시글의 유사도, 순위를 함께 저장해 나중에 설명 가능하게 만듭니다.

직접 입력 추천 흐름

직접 입력 추천은 게시글이 없어도 사용자가 가진 재료와 조건으로 추천을 만드는 경로입니다. 그래도 기존 커뮤니티 게시글을 검색해 근거로 붙이려는 RAG 흐름은 동일하게 사용됩니다.

게시글 추천과 같은 점 임베딩을 만들고, 기존 게시글과 비교하고, 품질 필터를 통과한 게시글만 커뮤니티 근거로 사용합니다.
게시글 추천과 다른 점 새 PostRagDocument를 저장할 게시글이 없기 때문에, 요청 문서는 검색 질문으로만 쓰입니다.
직접 입력 경로의 핵심은 buildDirectRagDocument()입니다. 사용자가 입력한 재료와 조건을 검색 가능한 문장으로 바꿔 기존 게시글과 비교할 수 있게 만듭니다.

함수 역할 카드

아래 함수들은 외울 대상이라기보다 “어느 책임이 어디에 있는가”를 잡기 위한 지도입니다. 함수 이름을 보면 요청 흐름을 다시 말할 수 있는 정도가 목표입니다.

입구와 공개 기능

getStatus()

OpenAI 키 여부, 임베딩 모델, pgvector 사용 가능 여부, 유사도 기준값을 화면에 알려줍니다.

상태 점검 환경 설정 확인
findLatest(postId)

특정 게시글에 이미 만들어진 최신 AI 추천이 있는지 조회합니다.

조회 공개 가능
create(postId, requesterId, dto)

게시글 기반 추천의 메인 흐름입니다. RAG 검색, LLM 추천, 이미지 생성, DB 저장을 순서대로 연결합니다.

게시글 기반 로그인 필요 RAG 핵심
createDirect(dto, requesterId)

게시글 없이 재료 목록과 조건만으로 추천을 생성합니다. 기존 커뮤니티 게시글 검색은 그대로 활용합니다.

직접 입력 검색 질문 생성

RAG 문서와 임베딩

buildRagDocument(post)

게시글 ID, 제목, 본문, 태그, 댓글 요약, 댓글 수, 조회 수를 하나의 검색용 텍스트로 묶습니다.

문서화 검색 재료
buildDirectRagDocument()

직접 입력된 보유 재료와 조건을 RAG 검색 질문처럼 정리합니다.

직접 입력 전용 게시글 없음
EmbeddingService.embed(text)

OpenAI 키가 있으면 OpenAI 임베딩을 쓰고, 없거나 실패하면 로컬 해시 임베딩으로 대체합니다.

벡터 생성 비용 분기 fallback
upsertRagDocument()

게시글의 RAG 문서와 임베딩을 PostRagDocument에 새로 넣거나 갱신합니다.

저장 재검색 준비

검색과 근거 판정

findSimilarPosts()

후보 게시글의 RAG 문서를 갱신하고 pgvector 검색을 시도합니다. 문제가 생기면 메모리 검색으로 대체합니다.

검색 조립 pgvector 우선
findSimilarPostsWithPgvector()

DB에 저장된 벡터와 요청 벡터의 거리를 비교해 가까운 게시글 후보를 가져옵니다.

주 검색 경로 벡터 거리
findSimilarPostsInMemory()

pgvector 검색이 실패했을 때 서비스 내부에서 코사인 유사도를 계산하는 안전장치입니다.

안전장치 품질 개선 주 경로 아님
buildSimilarPost()

검색된 게시글을 추천에 넘기기 좋은 근거 객체로 정리합니다. 댓글 근거, 태그, 재료 겹침, 부족 재료를 묶습니다.

근거 포맷 댓글 중심
isStrongSimilarPost()

유사도 기준, 댓글 근거 존재 여부, 최소 재료 겹침을 검사해 실제 RAG 근거로 쓸지 결정합니다.

품질 필터 근거 신뢰도
getRecommendationGrounding()

품질 필터를 통과한 게시글이 있으면 COMMUNITY_RAG, 없으면 GENERAL_AI로 분기합니다.

분기 정직한 근거 표시

재료와 추천 생성

extractIngredientsFromRagPost()

게시글 제목, 본문, 태그에서 보유 재료로 보이는 단어를 뽑습니다.

재료 추출 검색 필터 준비
normalizeIngredientTerms()

직접 입력 재료를 정리하고 별칭을 통일합니다. 예를 들어 달걀과 계란처럼 같은 의미를 맞춥니다.

정규화 별칭 처리
RecipeLlmService.createRecommendation()

OpenAI 키가 있으면 모델 호출로 추천을 만들고, 없으면 로컬 fallback 추천을 만듭니다.

최종 추천 LLM 또는 fallback
completeRecommendationDraft()

커뮤니티 근거에서 드러난 부족 재료를 추천 결과에 보강합니다.

결과 보정 근거 반영

DB와 근거 저장

RAG가 설명 가능하려면 추천 결과만 저장하면 부족합니다. “어떤 게시글을 참고했는가”도 같이 저장해야 나중에 화면에서 근거를 보여줄 수 있습니다.

모델 역할 RAG 관점에서 중요한 필드
PostRagDocument 게시글 하나를 검색 가능한 문서와 벡터로 저장합니다. documentText, embedding, embeddingModel, isStale
AiRecipeRecommendation AI가 만든 추천 결과를 저장합니다. grounding, menuName, reason, missingIngredients
AiRecommendationReference 추천 결과와 참고 게시글 사이의 연결을 저장합니다. postId, similarity, rank
중요한 구분
PostRagDocument는 검색을 빠르게 하기 위한 저장소이고, AiRecommendationReference는 추천 결과의 근거를 추적하기 위한 저장소입니다.

품질 기준

RAG에서 가장 중요한 것은 “비슷해 보이는 글을 무조건 근거로 쓰지 않는 것”입니다. 이 프로젝트는 세 가지 기준으로 참고 게시글을 걸러냅니다.

유사도 기준 기본값은 0.55입니다. 문맥이 너무 멀면 제외합니다.
댓글 근거 댓글 조언이 없는 글은 질문만 있는 상태라 추천 근거로 약합니다.
재료 겹침 기본값은 최소 1개입니다. 엉뚱한 재료의 글을 막는 필터입니다.
재료 겹침은 점수를 올리는 가산점이 아닙니다. “근거로 사용할 자격이 있는가”를 판단하는 문턱으로 보는 편이 더 정확합니다.
